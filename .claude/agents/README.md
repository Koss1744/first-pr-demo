# Агенты проекта внедрения GLPI

Субагенты Claude Code под роли проекта настройки GLPI (https://sd.hofi.su)
с нуля. Вызываются автоматически по описанию задачи или явно:
`@glpi-analyst ...`, `@glpi-admin ...` и т.д.

| Агент | Роль | Когда звать |
|---|---|---|
| `glpi-pm` | Руководитель проекта | План, оценка, риски, статусы, границы проекта |
| `glpi-analyst` | ITSM-аналитик | Процессы, каталог услуг, категории, SLA, права |
| `glpi-admin` | Администратор GLPI | Сущности, профили, справочники, шаблоны, правила, плагины |
| `glpi-integrator` | Инженер интеграций | AD/LDAP, почта, GLPI Agent, REST API, SSO |
| `glpi-migration` | Миграция данных | Перенос пользователей, активов, КБ, истории заявок |
| `glpi-qa` | Тестирование и приёмка | Тест-кейсы, проверка прав и SLA, пилот |
| `glpi-trainer` | Обучение и документация | Инструкции, регламенты, программа обучения |

## Порядок запуска

```
glpi-pm  →  glpi-analyst  →  glpi-admin  →  glpi-integrator  →  glpi-migration
                                        ↘  glpi-qa  →  glpi-trainer  →  запуск
```

Технической настройке всегда предшествует аналитика: без каталога услуг с
владельцами и ответственными группами `glpi-admin` не с чем работать.

## Артефакты

Агенты пишут результаты в `docs/glpi/`:

```
docs/glpi/
├── requirements.md        # требования (analyst)
├── service-catalog.md     # каталог услуг (analyst)
├── categories.md          # дерево категорий (analyst)
├── sla-matrix.md          # SLA/OLA и приоритеты (analyst)
├── roles-matrix.md        # роли, профили, права (analyst)
├── config-log.md          # журнал изменений конфигурации (admin)
├── integrations/          # AD/LDAP, почта, агент, API (integrator)
├── migration/             # маппинг полей, отчёты (migration)
├── test-cases.md          # приёмочные сценарии (qa)
├── guides/                # инструкции пользователю, L1, админу (trainer)
└── risks.md               # риски и открытые вопросы (pm)
```

## Ограничение

Прямого доступа к инстансу GLPI у агентов нет. Они готовят конфигурации,
инструкции, скрипты и проверочные команды — выполняет их администратор.
Ни один агент не должен сообщать, что настройка «выполнена»; корректная
формулировка — «подготовлено к выполнению».

## Секреты

В артефактах — только плейсхолдеры (`<LDAP_BIND_PASSWORD>`, `<API_TOKEN>`).
Реальные пароли, токены и учётные данные в репозиторий не попадают.
